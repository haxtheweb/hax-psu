# AGENTS.md — hax-psu (hax.psu.edu homepage SPA)

This file gives AI coding agents repo-specific instructions for `hax-psu`, the public front door for HAX at Penn State (https://hax.psu.edu/). For ecosystem-wide context (pillars, monorepo layout, DDD, CLI), see the `AGENTS.md` in `haxtheweb/haxcms-php` or `haxtheweb/praw`. This is a homepage SPA, NOT a HAXcms content site — there is no `site.json` or `pages/` directory here.

## Architecture

- **Frontend**: Single-page app. `index.html` hosts a `<hax-psu>` custom element; `src/hax-psu.js` is the LitElement implementation using the DDD design system and SimpleColors (DDD preferred; SimpleColors only for shades DDD lacks).
- **Backend**: Small PHP surface in `env/` (login via Penn State WebAccess, a webhook, a stats endpoint). Not a full CMS — authoring happens on the HAXcms service this site links to.
- **Deploy target**: `built/` is the committed artifact that gets served. It is regenerated by `npm run build` from `dist/` (rollup output) + `env/*` + `env/.htaccess` + `llms.txt` + `.well-known/`.

## Build pipeline

```
npm run build :=
  npm run screenshots       # Playwright + sharp → assets/screenshots/
  && npm run sync:content   # regenerate static/AI copies of the homepage from src/hax-psu.js
  && rimraf dist
  && rollup -c rollup.config.js   # bundle SPA → dist/ (+ workbox service worker)
  && npm run analyze -- --exclude dist built   # custom-elements.json
  && npm run build:agent-skills   # regenerate .well-known/agent-skills/ from ../praw/skills
  && rm -rf built
  && cp -r dist built
  && cp -r env/* built/
  && cp env/.htaccess built/
  && cp llms.txt llms-full.txt built/
  && cp -r .well-known built/
```

Other scripts:
- `npm start` / `npm run start:build` — web-dev-server dev / built preview.
- `npm run analyze` — Custom Elements Manifest analyzer (`cem analyze --litelement`); emits `custom-elements.json` (gitignored — generated, do not hand-edit).
- `npm run screenshots` — Playwright capture + sharp processing into `assets/screenshots/`.
- `npm run sync:content` / `npm run check:content` — regenerate (or verify) the no-JS / AI copies of the homepage from the rendered component; see "Agent-discovery wiring". Set `CHROMIUM_PATH` to use a specific Chromium binary.
- `npm run build:agent-skills` — `node scripts/build-agent-skills-index.cjs`; copies the curated HAX skill set from sibling `../praw/skills/` into `.well-known/agent-skills/` and writes `index.json`.

## Critical rules

- **Do NOT hand-edit `built/`** — it is a generated deploy target. Edit source (`src/`, `env/`, `index.html`, root files) and run `npm run build`.
- **Do NOT hand-edit `custom-elements.json`** — generated by `npm run analyze`.
- **Do NOT hand-edit `.well-known/agent-skills/`** — generated by `npm run build:agent-skills`. To change the curated set, edit the allowlist in `scripts/build-agent-skills-index.cjs` and re-run.
- **Do NOT run the ubiquity script** (ecosystem-wide rule). The agent is not allowed to run it.
- **Do NOT run a top-level monorepo build** (ecosystem-wide rule). This repo's build is `npm run build` from within `hax-psu/` only.
- **Do NOT block `.well-known`** in `.htaccess` — `env/.htaccess` already has a negative lookahead `(?!well-known)` so dotfile-deny rules skip it. Keep it that way; agent discovery + `security.txt` must stay reachable.
- **Do NOT modify files in `build/` or `node_modules/`** — edit underlying source instead (ecosystem-wide rule).

## Agent-discovery wiring (llms.txt + .well-known)

This repo publishes these agent-facing surfaces, all copied into `built/` at build time:
1. `/llms.txt` — LLM guide written for assistants answering questions about HAX@PSU (key facts, get-started links, docs, examples, support, discovery endpoints). Source of truth: `llms.txt` at repo root.
1a. `/llms-full.txt` — the full homepage content as Markdown. Also served for `/` when a client sends `Accept: text/markdown` without `text/html` (see `env/.htaccess`).
1b. Static light-DOM copy of the homepage inside `<hax-psu>` in `index.html` (`.static-content`). Crawlers and AI fetchers that don't run JS read this; the component's shadow DOM has no `<slot>`, so it is never displayed once the element upgrades.
   **`src/hax-psu.js` (plus `src/examples.mjs`) is the single source of truth for homepage copy.** `scripts/sync-static-content.mjs` renders the component in headless Chromium and regenerates, from its shadow DOM: the `.static-content` block in `index.html` (between `<!-- sync:static-content:* -->` markers), the `FAQPage` node of the JSON-LD in `index.html`, all of `llms-full.txt`, and the examples list in `llms.txt` (between `<!-- sync:examples:* -->` markers). Never hand-edit those regions; edit the component and run `npm run sync:content` (it also runs as part of `npm run build`). `npm run check:content` exits non-zero on drift and runs in CI (`.github/workflows/content-sync.yml`). The rest of `llms.txt` (key facts, link sections) stays hand-curated.
2. `/.well-known/security.txt` — RFC 9116 security contact. Source: `.well-known/security.txt`.
3. `/.well-known/agent-skills/index.json` — agentskills.io discovery v0.2.0 index of the curated HAX skills, with each skill's `SKILL.md` (+ `.md`/`.json`/`.txt` reference files) copied self-contained under `/.well-known/agent-skills/<name>/`. Generated by `scripts/build-agent-skills-index.cjs` from sibling `../praw/skills/`.

The curated set is the "normal HAX site" skill set (mirrors `haxcms-php/.well-known/agent-skills`, minus community integrations): `hax-a11y-audit`, `hax-claudehax`, `hax-content-authoring`, `hax-content-chunking-audit`, `hax-design-system`, `hax-managed-files`, `hax-site-building`, `hax-site-structure`, `hax-ubd-backward-design`, `hax-ubd-essential-questions`, `hax-ubd-grasps`, `hax-ubd-six-facets`, `hax-ubd-stage1`, `hax-ubd-stage2`, `hax-ubd-stage3`, `hax-ubd-unit-audit`, `hax-udl-audit`, `hax-webcomponent-dev`, `oerschema-audit`, `oerschema-integration-finder`.

To refresh the published skills after they change in `praw`, run `npm run build:agent-skills` (then `npm run build` when ready to regenerate `built/`). The build script only ships declarative content (`.md`/`.json`/`.txt`); it never copies executable artifacts (`.js`/`.cjs`/`.mjs`/`.sh`/`.php`/`.py`/...) into `.well-known/`.

## Code style & conventions

- **JavaScript-only, no TypeScript** (ecosystem-wide). `package.json` is `"type": "module"`.
- Use `globalThis` instead of `window` for global references (ecosystem-wide rule).
- Single quotes, avoid semicolons where possible, Prettier formatting.
- **DDD design system**: import from `@haxtheweb/d-d-d/d-d-d.js`; extend `DDD` directly (`class X extends DDD {}`), never `DDD(LitElement)`. Use DDD tokens for spacing, colors, icon sizes. Use `@haxtheweb/simple-colors` only as a fallback for shades DDD lacks.
- **Icons**: prefer `simple-icon-lite` (colorizable via light-DOM CSS `color`); for buttons prefer `simple-icon-button-lite`. Use DDD icon-sizing variables for height/width.
- Avoid optional chaining (`?.`) — the current toolchain has issues with it (ecosystem-wide rule).
- Avoid inline styles in demo/example HTML; prefer CSS classes or design-system variables.

## Security

- Report vulnerabilities via `/.well-known/security.txt` (GitHub security advisories on `haxtheweb/issues`, or `hax@psu.edu`).
- Do not commit API keys or secrets to `package.json`, `manifest.json`, or public files.
- Keep PHP in `env/` minimal; sanitize any user input.

## Working in this repo as an agent

1. Check the unified issue queue (`gh issue list`) before starting work.
2. Edit source files in `src/`, `env/`, `index.html`, or root — never `built/`, `dist/`, `node_modules/`, `custom-elements.json`, or `.well-known/agent-skills/`.
3. For agent-discovery files: edit `llms.txt` / `.well-known/security.txt` directly; regenerate `.well-known/agent-skills/` via `npm run build:agent-skills` (and edit the allowlist in `scripts/build-agent-skills-index.cjs` if the curated set should change).
4. When ready to regenerate the deploy target, run `npm run build` (note: this also runs the Playwright screenshot pipeline — ensure `npx playwright install` has run once).
5. Do not commit unless explicitly asked.
